حالة العقد

عناصر experiment الظاهرة في الـ public API موسومة experimental، ويستخدم الكود #[non_exhaustive] حيث يلزم. الأسماء والحقول قابلة للتغيير قبل استقرار هذه الـ API.

تصف أسماء الـ hooks مراحل دلالية، لا خطوات implementation قابلة للتبديل. ينفذها ember synchronously وبترتيب ثابت، بينما تصل كل معمارية إلى الحد نفسه عبر مسار عددي صريح خاص بها.

الـ lifecycle

يتكون generation run عادي وناجح من استدعاء واحد لـ on_model_loaded()، ثم استدعاء واحد لـ before_prefill()، ثم تقييم prefill واحد يمر عبر layer hooks وlogits hooks. بعده تمر صفر أو أكثر من تقييمات decode عبر الـ hooks نفسها، ثم يُستدعى on_generation_complete() مرة واحدة.

ترتيب ثابت وتنفيذ synchronous

لا تستأنف عملية التنفيذ حتى يرجع الـ hook الحالي. وإذا فشل، يتوقف generation الحالي ولا تعمل الـ hooks اللاحقة.

تعمل الـ hooks الستة التي تحمل tensors أولاً تحت phase=Prefill، ثم تحت phase=Decode في كل تقييم decode أحادي التوكن. ترقيم الطبقات يبدأ من الصفر ويتبع ترتيب تنفيذ النموذج.

واجهة الـ trait

name وحده إلزامي. كل method في الـ lifecycle ترجع افتراضياً بنجاح من دون تنفيذ عمل. تطبق التجربة المدمجة الـ methods التي تحتاجها فقط. 

pub trait Experiment: Send {
    fn name(&self) -> &'static str;

    fn on_model_loaded(
        &mut self,
        ctx: &ModelContext<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn before_prefill(
        &mut self,
        ctx: &ExecutionContext<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn before_layer(
        &mut self,
        ctx: &LayerContext<'_>,
        hidden: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn after_attention(
        &mut self,
        ctx: &LayerContext<'_>,
        attention_output: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn after_mlp(
        &mut self,
        ctx: &LayerContext<'_>,
        mlp_output: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn after_layer(
        &mut self,
        ctx: &LayerContext<'_>,
        hidden: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn before_logits(
        &mut self,
        ctx: &ExecutionContext<'_>,
        hidden: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn after_logits(
        &mut self,
        ctx: &ExecutionContext<'_>,
        logits: &mut TensorAccess<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }

    fn on_generation_complete(
        &mut self,
        ctx: &GenerationContext<'_>,
    ) -> Result<(), ExperimentError> { Ok(()) }
}

أنواع الـ context

يعرّف العقد أربعة أنواع context. كلها بُنى خفيفة وimmutable تستعير البيانات التي تحتاجها. لا تعرض token buffers، ولا metadata GGUF الكاملة، ولا weight handles أو caches أو تفاصيل الـ backend الداخلية.

الـ context الحقول تُستخدم في
ModelContext العائلة، ومعرّف اختياري، والـ architecture، وعدد الطبقات، وحجم hidden state تحميل النموذج؛ وتدخل ضمن بقية الـ contexts
ExecutionContext النموذج، والـ phase، وموضع البداية، وعدد input tokens، وطول التسلسل الناتج، وحالة tracing hooks الخاصة بالـ prefill والطبقات والـ logits
LayerContext execution context ورقم طبقة يبدأ ترقيمه من الصفر أربعة tensor hooks في كل طبقة
GenerationContext النموذج، وعدد prompt tokens، وعدد التوكنات المولدة، وعدد تقييمات decode، وحالة tracing عند الاكتمال الناجح

موضع التنفيذ

start_position
الموضع المطلق لأول input token في هذا التقييم
input_token_count
عدد input tokens التي يعالجها هذا التقييم
sequence_length
start_position + input_token_count بعد إدخال التوكنات الحالية
token_position()
يعيد موضعاً مطلقاً فقط للتقييمات التي تحتوي token واحداً، كما في decode العادي؛ وإلا يعيد None

TensorAccess

TensorAccess هي view mutable وغير مالكة فوق activation موجودة. في v0.1 تكون activation contiguous وثنائية الأبعاد ومن نوع f32، ولها shape ثابت [rows, columns]. يملك runtime allocation والـ buffer، ولا ينشئ نسخة خاصة بالـ hook.

المسموح
  • فحص shape وdtype؛
  • قراءة قيم f32 المكشوفة؛
  • تعديل القيم داخل الـ slice الموجودة؛
  • تصفير القيم الموجودة.
غير المسموح
  • تغيير الحجم؛
  • إعادة تخصيص الذاكرة؛
  • تغيير shape أو dtype؛
  • استبدال الـ buffer أو أخذ ملكيته؛
  • الوصول إلى الأوزان أو caches أو scratch storage أو بيانات التوكنات.
let shape: &[usize; 2] = tensor.shape();
let dtype: TensorDType = tensor.dtype();
let observed: &[f32] = tensor.values();

// explicit intervention on the same allocation:
for value in tensor.values_mut() {
    *value *= 0.5;
}

// or replace existing values with zero:
tensor.zero();

لا تفرض الواجهة نفسها سلوك observation-only عبر نظام الأنواع. يقع هذا الضمان على implementation: استخدام values() يحافظ على التنفيذ، بينما قد يغيّره values_mut() أو zero().

دلالات عائلات النماذج

تشير الأسماء المشتركة إلى الحدود الدلالية نفسها، لكنها لا تعني أن الـ blocks الداخلية متطابقة. تصل كل معمارية إلى الحد عبر ترتيبها وعملياتها العددية الخاصة؛ ولا تمحو واجهة الـ hooks هذه الفروق.

الحد LLaMA / Qwen3 Gemma 4
after_attention بعد O projection، وقبل residual addition بعد O projection وpost-attention RMS norm، وقبل residual addition
after_mlp بعد down projection، وقبل residual addition بعد down projection وpost-FFN RMS norm، وقبل residual addition
after_layer بعد MLP residual addition بعد عمليات الـ residual وPLE وscaling لناتج الطبقة
before_logits hidden state لآخر token بعد final normalization hidden state لآخر token بعد final normalization
after_logits LM head output ناتج LM head بعد final logit softcap
فروق Qwen تبقى صريحة

يستخدم Qwen3 تنفيذ الـ block المشترك مع عائلة LLaMA، مع الحفاظ على split-half RoPE وQK normalization وترتيب العمليات الخاص به. اسم الـ hook المشترك لا يجعل هذه الدلالات قابلة للتبادل.

في LLaMA، تعمل single-token hooks النشطة مباشرة على decode workspace مخصصة مسبقاً؛ ولا تفرض الـ hooks generic tensor path. ويبقى dispatch في Gemma بين مساري MLP الـ packed والـ generic من دون تغيير.

المسار المعطّل

generation العادي لا يبني ExperimentRunner أصلاً. دوال النموذج generic على نوع hooks adapter، وتستخدم عند التعطيل DisabledHooks، وهو adapter بحجم صفر. والـ methods المعطلة داخله #[inline(always)] no-ops. 

pub(crate) struct DisabledHooks;

impl<T, E> LayerHooks<T, E> for DisabledHooks {
    #[inline(always)]
    fn after_attention(
        &mut self,
        _layer_index: usize,
        _tensor: &mut T,
    ) -> Result<(), E> {
        Ok(())
    }
    // the other disabled methods have the same shape.
}
ضمان المسار المعطّل

في المسار المعطّل الذي جرى التحقق منه، لم يبق أي experiment-related dispatch في الكود الناتج. ولم يظهر أي نمو في عدد allocations لكل طبقة بعد warm-up، وبقيت قياسات A/B المضبوطة للـ prefill والـ single-token decode ضمن ضجيج القياس.

يستمر decode المحسّن في LLaMA باستخدام workspace المخصصة مسبقاً، ولا تفرض الـ hooks الـ generic tensor path، ولا تغيّر dispatch الـ MLP بين packed وgeneric في Gemma.

Failure path

تنفيذات الـ hooks ترجع ExperimentError. يغلّف ExperimentRunner هذا الخطأ داخل ExperimentFailure قبل وصوله إلى مسار الأخطاء العادي في ember.

الـ hooks synchronous. أي فشل يوقف generation الحالي؛ لا يُسجل الاكتمال كنجاح، ولا تعمل الـ hooks اللاحقة.

حدود واجهات الفحص

قيم التجربة النشطة ليست قيم dump

في v0.1، التجارب النشطة لا تعمل مع استخراج hidden states أو probes أو --dump-layers أو --dump-logits، ولا مع أوامر demo أو interactive أو benchmark الفرعية. تُرفض هذه التركيبات بدلاً من عرض قيم ذات دلالة ملتبسة.

لم يعرّف ember بعد هل ينبغي أن تعرض واجهات الفحص القيم قبل intervention أم بعده. وهذا سؤال دلالي غير محسوم، لا نقص في وسيلة نسخ البيانات.

tracing العادي من دون تجربة، واستخراج hidden states، وlayer dumps، وlogits dumps، وتقارير benchmark، وdispatch للـ packed kernels كلها تبقى كما هي. يمكن تفعيل structured tracing مع تجربة، وتظهر حالته داخل ExecutionContext، وهي immutable. لكن الـ hooks لا تستبدل trace stream ولا تعيد تعريفه.
