# Ember 1.0 contract audit — working evidence

Status: in progress, 2026-09-27. The candidate is the uncommitted worktree
based on `85c2382f43d6976b95b5d0fe22a2312c9157f8f7`; it is not a tagged release.
This audit does not close the complete 1.0 roadmap.

## Contract fixes

| Boundary | Finding | Change and evidence |
|---|---|---|
| Nested contract versions | A correctly rehashed bundle could declare unknown experiment/hook/plan versions | Reject unsupported versions before interpreting payloads; resealed negative fixtures isolate each failure |
| Stored plan identity | A self-consistent plan could disagree with the semantic manifest | Verify both schema and referenced plan hash |
| JSON payload determinism | Dependency feature unification could expose map insertion order | Sort all deterministic JSON/JSONL keys recursively; test reordered nested metadata and arrays |
| Strict tagged objects | Serde silently ignored fields on unit variants | Private strict wire forms preserve the public enum while rejecting unknown fields for selectors, operations and sources |
| File inventory | Extra files, missing checksum entries and symlinks were not rejected | Check regular-file inventory, checksum coverage and duplicates; reject symlinks/special files before reading the manifest |
| Test isolation | Concurrent tests could get the same timestamp directory | Add an atomic sequence to fixture directory names |
| Historical hash compatibility | An actual v0.5 writer hashed insertion order | Recognize the legacy encoding only for released 0.5.0/0.5.1 and 0.6.0–0.6.8 producers; preserve stored identity and report the encoding |

Unknown fields are rejected rather than silently migrated. The enum wire
representation, hook identifiers and intervention timing are unchanged.
Directory verification assumes an immutable bundle; it is not a filesystem
snapshot resilient to concurrent mutation. Resource limits and all remaining
corruption cases still need a full release audit.

## Required-field review

The strict raw experiment schema requires `schema`, `experiment`, `model`,
`inputs`, and `output`. Their required child fields are experiment `name`, model
`path`, output `directory`, and each input's `id`/`text`. A capture requires
`id`, `site`, and `tokens`; intervention definitions require `id`, `site`,
`tokens`, and `operation`, with a source required by consuming operations.
Required-field deletion tests cover the top-level/core/capture boundaries.
Existing operation/source tests cover valid combinations and finite parameters.
The remainder of the field-by-field negative matrix remains under review.

The schema guide had examples inconsistent with the parser: layer ranges use
`end` (exclusive), a single layer is `[n]`, span `subtokens` is required, and
normalization is the string `"nfc"`. The guide now describes the existing wire
format instead of promising unsupported input forms.

## Open Python timeout boundary finding

The rebuilt development binding accepts finite positive `timeout_secs=1e300`
in `ember.diff`, then panics in `Duration::from_secs_f64`. Reproduction raises
`pyo3_runtime.PanicException` instead of the binding's documented input-error
path. Existing timeout tests cover zero, negative, NaN and infinity but omit
finite overflow. The shared `run_diff_corpus` implementation also uses the
infallible conversion after the same incomplete bounds check and after output
and seed preparation; this second path is source-confirmed, not yet a runtime
reproduction. Evidence: local `python-timeout-audit` transcript.

Before 1.0, replace these conversions with checked duration construction and
reject invalid timeouts before filesystem/subprocess work. Add regression cases
for finite overflow in both Python functions and the shared Rust corpus entry
point, preserving ordinary timeout behavior and the existing exception contract.
Compilation is deferred while the isolated K-quant timing matrix runs. This is
an open correctness finding, not a completed fix or compatibility freeze.

The regression tests now reproduce two failures against the existing binding:
`diff` panics on finite overflow, and `diff_corpus` reaches seed-file loading
before timeout rejection. Four existing invalid-number cases pass. Candidate
source now uses `Duration::try_from_secs_f64`: Python maps overflow to
`ValueError`, and the shared Rust corpus entry rejects it before creating output
or reading seeds. Added Python and Rust tests require rejection before filesystem
work. Targeted rustfmt and diff whitespace checks pass. The measured benchmark
binary and installed Python extension have not been rebuilt; passing execution
of the changed implementation remains pending and this finding is not closed.

parses. Normalization and range step remain optional. Core TOML deletion tests
cover top-level objects, experiment name, model path, output directory, input
id/text, and capture id/site/tokens. These are distinct deserialization tests,
not proof of model-dependent resolution or every malformed value.

The operation source rule is `replace`/`interpolate`/`add-delta` require a
source; `zero`/`scale`/`restore-original` do not consume one. The Rust field
comment omitted the scale exception and is corrected to match
`requires_source()` and the existing schema guide. Runtime behavior is
unchanged. A complete required-field acceptance review must still connect
parser, resolver, guide examples and candidate test results; this source
inspection alone does not close that milestone.

## Intervention text-selector validation gap

Field review found that `ExperimentSpecV1::validate` enforced non-empty text
for capture span selectors but omitted the equivalent intervention check.
The CLI `experiment validate` uses this validator, so an intervention could
receive a successful specification verdict before its text requirement was
checked later during token resolution. The implementation now checks only the
intervention's selected inputs and reports `interventions[index].tokens`.

The new regression covers matched-span and byte-span, rejects a selected empty
input, accepts the same empty input when it is not selected, and preserves
position-only selector behavior. Focused default/headless-MSRV spec suites are
now verified: 19 `v05::spec::tests` pass on Rust 1.98.1 default and Rust 1.92.0
headless in the isolated `target/contract-diagnostics`, including
`intervention_text_selectors_reject_only_selected_empty_inputs`. Evidence is in
`intervention-text-validation` (`tests-rerun.log`, `status.json`). This is a
validation fix, not a change to tensor arithmetic or old identities.

## Required experiment fields: parser-to-resolver checklist

Reviewed against `RawExperimentSpec`/`RawDefinition`, strict tagged wire types,
`resolve`/`validate`, the schema and intervention guides, and the morphology
examples. Every row below is presence-required unless the variant does not
apply. Defaultable fields are excluded deliberately, not silently treated as
required. `required_fields_cannot_be_defaulted_away` covers the core TOML rows;
`every_tagged_variant_requires_its_declared_fields` independently deletes every
required key in the nested typed rows after verifying a complete object parses.

| Boundary | Required keys | Resolution / semantic check |
| --- | --- | --- |
| Experiment root | schema, experiment, model, inputs, output | Exact schema identifier; at least one input |
| experiment | name | Non-empty, path-safe identifier |
| model | path | Retained path; file identity/access checked in model preparation |
| each input | id, text | Unique safe ID; text retained verbatim, span requirements checked on selected inputs |
| output | directory | Non-empty path; publication/overwrite enforced by writer |
| each capture | id, site, tokens | Unique safe ID; site enum; selected inputs and layer/site compatibility |
| each intervention | id, site, tokens, operation | Unique safe ID without capture collision; operation/source validation |
| prompt-final selector | kind | Complete model-input final position |
| absolute-token selector | kind, index | Model-input position bounds during token resolution |
| relative-token selector | kind, offset_from_end | Bounds during token resolution |
| generated-step selector | kind, step | Generation enabled; 1-based decode addressing checked during planning |
| matched-span selector | kind, text, occurrence, subtokens | Exact occurrence and token overlap; normalization defaults to none |
| byte-span selector | kind, start, end, subtokens | Nonempty ordered UTF-8 span and token overlap |
| layer range | start, end | End exclusive; default step 1; step/range/model bounds before allocation |
| replace/zero/add-delta/restore-original operation | kind | Typed operation; source/snapshot semantics as documented |
| scale operation | kind, factor | Finite factor; no source consumed |
| interpolate operation | kind, alpha | Finite alpha; source required |
| inline-vector source | kind, values | Nonempty vector; runtime columns/rows checked |
| capture-from-current-run source | kind, capture_id | Known capture; input/layer/source readiness checked in execution |
| capture-from-bundle source | kind, bundle_path, capture_id, input_id, layer | Verified bundle plus model/tokenizer/site/layer/shape checks |
| zero source | kind | Zero row constructed for target shape |

A source is conditionally required for replace/interpolate/add-delta, enforced
by `validate_self`; zero/scale/restore-original do not consume one. Optional
execution/generation blocks, capture/intervention lists, selectors/defaults,
and compatibility flags preserve omission provenance through `RawDefinition`.
Unknown fields and unsupported tags are rejected by strict deserialization.

This review found the intervention empty-text gap fixed above and an outdated
cross-layer example in `docs/interventions.md`. That example is now explicitly
historical; the current guide supplies the same-layer source for the pinned
morphology workflow and preserves the old artifacts. The new validator is now
verified by the 19 passing focused spec tests on both toolchains (see the
section above). The roadmap's required-field review checkbox remains gated on
the remaining parser/resolver/example/negative-test connections, not on this fix.
