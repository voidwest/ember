# Public surface inventory for the 1.0 review

Source review: 2026-09-27, development tree based on
`85c2382f43d6976b95b5d0fe22a2312c9157f8f7`. This inventory identifies review
boundaries; it does not declare new stability guarantees or narrow existing
CLI promises. The package was 0.6.8 at this review and now reports `1.0.0` in
the tree (the `v1.0.0` tag is held). The final candidate must validate the
complete supported surface before the 1.x policy is frozen.

## CLI

`src/main.rs::Commands` declares these top-level commands:

`extract`, `native-logits-reference`, `validate-run`, `validate-backends`, `compare-artifacts`, `bench-decode`, `bench-lifecycle`, `inspect-plan`, `kv`, `inspect`, `diff`, `diff-corpus`, `multimodal`, `audio`, `video`, `voice`, `tts`, `score-batch`, `handoff-inject`, `intervene-score`, `collect-spans`, `experiment`, `manifest`, `evidence`, `agent`, `trace`, `gui`, `web-gui`.

The no-subcommand generation route and its flags are also public CLI behavior.
`voice` requires the `audio` feature; native `gui` requires `gui`; `web-gui`
is present in headless builds. The `experiment` family contains `validate`,
`run`, `inspect`, `verify`, `compare`, `reproduce`, and `tokenize`. Its semantic
contract is shared by both GUIs. Diagnostic commands remain in this inventory:
their presence and documented arguments cannot be silently removed merely
because performance numbers or human-readable reports are diagnostic.

Before freezing: inventory every command's flags/defaults, nested commands,
output formats, exit paths and overwrite behavior. The existing usage contract
lists exits 0 (success), 1 (runtime failure), 2 (usage), 3 (verification verdict),
and 4 (cancellation). Check command-specific behavior against that list rather
than assuming every failure already uses the intended code.

A runtime help snapshot from the verified debug candidate records 54 command
nodes (including the root), 27 top-level commands, positional usage, options,
defaults and possible values as exposed by Clap. Each help invocation exited 0;
the binary hash and raw text are retained in local `cli-surface-snapshot`.
The difference from the 28 source-declared commands is the disabled opt-in
`voice` feature. This is a default-feature help inventory, not optional-audio
acceptance or proof that every command's execution/overwrite behavior is correct.

The exit-path review found and corrected two experiment handlers that directly
exited with inconsistent codes. `experiment verify` is now process-tested on
default and headless MSRV builds for success 0, failed checksum verdict 3, and
usage error 2; historical identity compatibility also passes. Failed reproduction
now returns the shared verdict error, but a runtime failure-branch reproduction
check remains open. See `experiment-exit-verified` and the contract audit.

## Serialized contracts and extension review

| Boundary | Version representation / existing reader rule |
|---|---|
| Experiment | `ember.experiment.v1`; strict fields and exact supported version |
| Bundle | `ember.bundle.v1`; nested experiment/hook/plan versions verified |
| Hook | six named sites; hook schema 1, ordering/addressing in research contract |
| Execution plan | integer `PLAN_SCHEMA_VERSION = 1` |
| KV snapshot | `ember.kv-snapshot.v1` |
| Agent trace | `ember.agent.trace.v1`; trace docs require ignoring unknown fields and preserving unknown event types |
| Differential report | `ember.diff.v1` |
| Legacy activation artifacts | `0.2.0-experimental` |
| Signed evidence | `signed-evidence-v1` |
| Run manifest | manifest schema 2; new identity v2 recursively sorted, historical v1 insertion-order digest preserved; versions and digest checked |

Strict experiment/bundle field rejection must not be generalized to every
format: agent traces intentionally have a different extension rule. Likewise,
a matching manifest digest alone does not establish semantic version support.
Review each reader/writer pair, required fields, unknown versions, malformed
inputs and historical fixtures before making a cross-format compatibility claim.

Future hook sites, tensor layouts, source addressing, operations and identity
rules need an explicit versioning decision when old readers would reject or
reinterpret them. Optional additions are not automatically compatible with a
strict reader. The next-feature extension review remains open; this inventory
does not approve schema changes or a 1.x freeze.

## Extensibility review

The 1.0 line fixes the serialized anchors named in
[research-contract section 19](../v05-research-contract.md) with fail-closed
unknown-major and required-field behavior. The following planned directions can
extend the interface without another major redesign, because each is either an
optional recognized field, a new enum/operation variant that old strict readers
already reject rather than misread, or a new schema version:

- **New hook sites.** Hook meaning is versioned (`ember.hook.v1`); a new site
  increments the hook schema and old readers reject it, so no existing bundle is
  reinterpreted. Addressing rules are already explicit (site/layer/position).
- **New intervention operations or token selectors.** Operations and selectors
  are strict tagged unions: an unknown tag fails closed, so a new variant is
  additive at the reader that supports it and a clean failure at the reader that
  does not.
- **New tensor dtypes or layouts.** Dtype and shape are checked before use; a new
  dtype is a new enum value that old readers reject rather than coerce, and plan
  identity carries `kernel_revision`.
- **New optional metadata.** Optional inputs/generation/compatibility blocks
  preserve omission provenance through `RawDefinition`; a newly recognized
  optional field is minor-compatible, an unknown one is rejected by strict
  readers.
- **New run-manifest fields.** Identity is versioned
  (`execution-identity-v1`/`v2`) and recursively canonicalized; a new identity
  schema is a new version with retained old-reader support.

The only pre-1.0 changes that alter scientific output are the correctness fixes
listed in the [candidate migration notes](../migration-to-1.0.md); they are
documented as preserve-rerun-compare, not silent. The `voice` command stays
feature-gated (`audio`) and is out of the default surface; adding optional audio
does not revise any stable anchor. No remaining incompatible change is required
before tagging 1.0, beyond shipping these documented corrections.
