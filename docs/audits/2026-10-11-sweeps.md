## 1. Map and boundaries

- User-facing commands/APIs: `ember experiment validate|run|verify|compare|inspect`
  with a spec that has a `[sweep]` table, or with a sweep directory.
- Source entry points: `SweepDefinition::parse`, `points` and
  `check_moved_bundle_sources` in `src/v05/sweep.rs`;
  `EffectDefinition::parse`, `apply_effect` and `summarize` in
  `src/v05/effect.rs`; `run_sweep` and `run_verify_sweep` in
  `src/cli_experiment_sweep.rs`.
- Adjacent subsystems and handoffs: the shared pass and prefix reuse
  (`src/cli_experiment_shared.rs`); bundle-source resolution
  (`load_bundle_source` in `src/v05/runner.rs`); bundle verification
  (`src/v05/verify.rs`).
- Persistent artifacts or schemas: `sweep.json` (`ember.sweep.v1`),
  `sweep.csv`, `sweep-effect.csv`, `sweep.toml`, and one `ember.bundle.v1`
  bundle for each point and the baseline.
- Environment switches and feature gates: none new.
- External references or trusted implementations: none. The statistics
  are self-contained. The SplitMix64 test checks the published first output
  for state 0.
- Supported targets and deliberate non-goals: the only metric is
  `logit(target) - logit(foil)`. Sources move with layers only: no transfer
  across layers or sites, and no `positions` with moved sources. The GUI
  sweep does not show effect statistics.

## 2. Contracts and invariants

- Ownership/lifetime and resource limits: `resamples` is 100 to 100,000;
  `confidence` is inside (0, 1); `layer_count` is at most the loader limit
  (4,096). `verify` checks these values from `sweep.json` again before they
  size an allocation.
- Shape, encoding, safety, or error behavior: the effect capture must be at
  site `logits`, store rows, and give exactly one row for each input. Every
  input needs a target. Token text must encode to exactly one token. A
  non-finite logit fails the run. Each failure is a typed spec error or a
  failed check, not a panic.
- Numerical, determinism, trace, or hook boundaries: the summary uses only
  IEEE add, multiply, divide and square root, in a fixed order, from the
  per-input effects that `sweep.json` records. No hook semantics changed.
- Compatibility/provenance requirements: new fields are optional and are
  not serialized when absent, so earlier sweeps keep the same files and
  `sweep_hash`. Strict readers in earlier binaries reject the new fields.
  Point bundles are unchanged `ember.bundle.v1` bundles, and each derived
  spec names its moved source layer.
- Reference/oracle path versus optimized path: not applicable. The effect
  reads captured logits from bundles of any execution mode.

## 5. Newcomer handoff

A sweep runs one experiment for each point (layer, position or alpha) and
binds the bundles with `sweep.json`. With `[sweep.effect]`, it also gives a
metric for each input and a summary over the inputs. It must not change the
bundles that a derived spec gives alone, and it must not trust `sweep.json`.
Start with
`cargo test --no-default-features --bin ember -- cli_experiment_sweep`,
which runs every sweep feature on a synthetic model. The real-model examples
are `examples/experiments/capital-*.toml`. They need the pinned model in the
repository root, which `scripts/download_models.sh research-example` gets.
